# DMX Gateway for Home Assistant

Local Home Assistant integration for the ESP32 DMX Gateway Product API.

## Features

- Connects to a gateway by host, port and the device-specific connection code.
- Uses the stable gateway ID, rather than its DHCP address, as the HA identity.
- Provides dimmable light entities for every configured DMX channel and a
  blackout switch.
- Exposes gateway diagnostic sensors on the gateway device page: uptime,
  free memory, DMX frame rate, transmission errors, runtime topology,
  transition count, and NVS persistence health.
- Includes a standard Options Flow: add, edit and delete DMX devices; set the
  first DMX address, channel count and channel names.
- Includes per-channel default fade settings: enable/disable automatic fades
  and choose the time for a full 0–100% transition (1–10 seconds). An explicit HA
  `transition` value overrides this default.
- Preserves device and channel IDs during edits, so existing entity IDs stay
  stable.

## Installation in Home Assistant

1. In HACS, add this GitHub repository as a custom **Integration** repository.
2. Install **DMX Gateway** and restart Home Assistant.
3. On a new native gateway, scan the commissioning label, connect your phone
   to `DMX-<last six MAC characters>`, then open `http://192.168.4.1/`.
   Enter the home Wi-Fi name and password. Copy the **connection code** shown
   once by that page.
4. In Home Assistant open **Settings → Devices & services → Add integration →
   DMX Gateway**, then enter the gateway address, port `8080` and that code.

There is no GitHub token, Home Assistant developer credential or Wi-Fi
password to enter in Home Assistant. The connection code is generated by the
gateway during first-run setup and authorizes only its local HTTP API.

The setup form asks for:

- **Host** — the gateway IP address (for example, `192.168.2.109`), preferably
  reserved in the router DHCP settings;
- **Port** — `8080` for the gateway HTTP Product API;
- **Connection code** — the device-specific code shown by the first-run setup
  page. It is stored by Home Assistant as the local API credential.

The connection code is not a GitHub, HACS, Home Assistant or Wi-Fi password.
It is device-specific and never included in this repository. A factory build
uses a different individual setup code printed on the device label to protect
the temporary Wi-Fi access point. Never publish either code or a firmware
binary that contains a setup-code value.

For an already provisioned device, the installer obtains the connection code
from its owner or private commissioning record. HACS cannot recover a lost
code; the device must be re-provisioned with the documented physical recovery
procedure.

After setup, open the **SkyDance S1-DR** device page. Each channel exposes
three controls: **Включать плавно**, **Действие после подачи электропитания**
(`Включен`, `Выключен`, `Состояние при отключении`) and the full-range fade
**Время увеличения яркости с 0 до 100 %** (1–10 seconds). An explicit
`transition` value in a Home Assistant light action overrides the channel default.

The integration talks to the gateway over its authenticated HTTP Product API
on port 8080. The deployed ESPHome API on port 6053 remains a migration
fallback for existing installations, but it is not used for DMX commands by this
integration. Diagnostic sensors are exposed from the HTTP `/v1/diagnostics`
endpoint in the same style as ESPHome diagnostics.

For the current deployed ESPHome firmware, use the already issued local API
token from the device owner; its retrofit path is different from the native
first-run flow above. The integration supports both Product API paths without
requiring an ESPHome development credential.

## Development

The package source is under `custom_components/dmx_gateway`. This repository
contains no Wi-Fi credentials, bearer tokens, SSH keys or firmware binaries.
